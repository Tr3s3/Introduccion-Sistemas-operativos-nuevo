# 1.4.4 Máquinas virtuales, hipervisor, JVM y CLR

> [!abstract] En una frase
> Una **máquina virtual** simula una computadora completa sobre una real. El **hipervisor** reparte el hardware físico entre varias VMs aisladas. La **JVM** y el **CLR** son máquinas virtuales de **proceso**: simulan un entorno de ejecución, no el hardware entero.

## Desarrollo
- **Máquina virtual:** abstracción que simula una computadora o un entorno de ejecución.
- **Hipervisor/VMM (Virtual Machine Monitor):** reparte CPU, memoria y dispositivos entre las VMs y las aísla. 
  - **Tipo 1 (bare metal):** corre directo sobre el hardware (ej. VMware ESXi, Hyper-V en server).
  - **Tipo 2 (hosted):** corre como aplicación sobre un SO anfitrión (ej. VirtualBox, VMware Workstation).
- **Usos:** consolidación de servidores, pruebas, aislamiento, ejecutar varios SO en una misma máquina.
- **JVM / .NET CLR (TP1, pregunta 22):** no simulan todo el hardware; ejecutan **bytecode** (o IL) en un entorno que administra memoria, tipos y seguridad. Son VMs de **proceso**.

| | Hipervisor | JVM / CLR |
|---|---|---|
| Qué simula | Una computadora completa | Un entorno para un programa |
| Qué ejecuta | Sistemas operativos invitados | Bytecode / IL |
| Dónde corre | Sobre hardware o sobre un SO host | Como proceso dentro de un SO |
| Aislamiento | Entre máquinas virtuales/SO | Dentro del runtime del proceso |

## Cómo responderlo en el final
"El hipervisor simula hardware completo para correr varios SO aislados. La JVM y el CLR son VMs de proceso: ejecutan bytecode y no reemplazan al SO."

> [!warning] Errores típicos
> - Llamar "máquina virtual" a la JVM como si simulara hardware físico.
