# 2.6.1 Comunicación entre procesos (IPC)

> [!abstract] En una frase
> Los procesos se comunican por **pipes**, **colas de mensajes**, **memoria compartida** o **sockets**. Cada mecanismo cambia el costo y la necesidad de sincronizar.

## Desarrollo
| Mecanismo | Cómo funciona | Ejemplo / nota |
|---|---|---|
| **Pipe** (tubería) | Un proceso escribe y otro lee; flujo de bytes, normalmente unidireccional | `ls \| grep txt` en el shell; pipe con nombre/FIFO para procesos no emparentados |
| **Cola de mensajes** | El SO mantiene mensajes en un buzón/cola; `send`/`receive` | Buena para desacoplar procesos; puede ser bloqueante o no |
| **Memoria compartida** | Varios procesos mapean la misma región de RAM | El más rápido, pero **requiere sincronización** (semáforos/mutex) |
| **Socket** | Comunicación por endpoint (local o red) | Cliente/servidor; funciona entre máquinas distintas |
| **Señales** | Notificación asincrónica simple | `SIGTERM`, `SIGKILL`; no transporta datos complejos |

> [!tip] Criterio de examen
> Si te piden comparar: memoria compartida = rápida pero necesita sincronización; mensajes/sockets = más desacoplados y útiles en red; pipes = simples para flujo lineal de datos.

## Cómo responderlo en el final
Nombrar los cuatro, dar un ejemplo de pipe en el shell y remarcar que la memoria compartida exige semáforos o mutex.
